# 3. Harness defect and remediation

## Ruling: DISCLOSURE AND CONVERSION ACCEPTED

The disclosed defect is material:

> A synchronous test wrapper cannot catch assertions that execute later inside a promise-returning callback unless the asynchronous work is itself awaited by the harness.

The corrected harness now refuses a test callback that returns a promise rather than silently recording it as passed.

The affected suites have been converted so asynchronous setup and behavior finish before synchronous assertions are registered.

The package includes the converted source and a complete rerun, rather than relying on results generated by the defective pattern.

The newly exposed `invalid-id` wording defect confirms that the re-audit was not merely ceremonial.

## Confidence ruling on earlier progress approvals

# 4. Final harness evidence requirement

Before final Commit 10 release approval, add a small harness regression suite proving the harness contract itself.

Required named checks:

- **HARNESS-01:** A synchronous assertion failure marks the suite failed.
- **HARNESS-02:** A promise-returning `test()` callback is refused and cannot print a false pass.
- **HARNESS-03:** A rejected deferred scenario marks the suite failed.
- **HARNESS-04:** `report()` waits for all registered deferred scenarios.
- **HARNESS-05:** A converted asynchronous scenario performs its asynchronous work before registering synchronous assertions.
- **HARNESS-06:** The runner exits nonzero for each failure mode above.

This is a final-evidence requirement, not a reason to delay rendered conflict-center work.

For future tests, asynchronous work must be represented by a promise registered with the harness or completed before synchronous `test()` assertions are registered. Do not place unreturned asynchronous callbacks inside a synchronous `test()` body.
